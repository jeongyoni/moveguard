# MoveGuard 프로젝트 설명서

처음 보는 사람도 이해할 수 있게 "왜 · 무엇을 · 어떻게 · 결과"를 쉬운 말로 정리한 문서입니다.
(설치·실행 방법은 [README](../README.md), 발표 흐름은 [docs/DEMO.md](DEMO.md) 참고)

---

## 1. 한 줄 요약

> **MoveGuard는 시스원 MSP 사업부의 기술영업 도구입니다.** 고객이 **운영 중인 환경**을 **"무료 헬스체크"**로 점검해 손봐야 할 리스크(지원종료·인증서·백업 등)를 선제 발견하고(즉시 조치/양호 판정 + 해결 방법), 발견된 리스크를 **MSP 운영·보안·백업·DR 서비스 수주로 연결**합니다. 판정은 **규칙 + ML** 하이브리드로 자동화돼 있고, 고객 리포트 문장은 **규칙 기반으로 자동 작성**합니다(사내 로컬 LLM 연동은 로드맵).

## 2. 누구를 위한 도구인가 — MSP 기술영업

고객의 이전 의사결정은 **영업 멘트가 아니라 기술 신뢰**로 움직입니다. MoveGuard는 그 신뢰를 만드는 **기술영업의 입구**입니다.

- **일반 영업이 뚫기 어려운 지점** — 인프라·운영 담당자는 "믿을 수 있는 근거"를 봅니다. MoveGuard는 규칙 13개 진단 리포트라는 **기술 증거**로 신뢰를 삽니다.
- **거절하기 어려운 접근 명분** — "운영 환경을 무료로 진단해드리겠습니다" → 콜드 세일즈보다 문이 열립니다. **기술이 영업의 입구**가 됩니다.
- **제안서 차별화** — 경쟁사는 "잘하겠습니다", 우리는 **"당신 환경의 위험 N건·차단 N건, 근거까지"**.

**영업 흐름**

| 단계 | MoveGuard의 역할 |
| --- | --- |
| **진입** | "무료 운영 헬스체크"라는 기술 미끼 → 미팅 성사 |
| **신뢰** | 즉시 조치 필요 + 구체 리스크(EOL·인증서·백업) 제시 → "이거 큰일" 공감대 |
| **수주** | 리스크를 해결하는 **운영·보안·백업·DR(MSP) 서비스 계약**으로 확장 |
| **재접점** | 조치 후 **재진단(개선 리포트)** → 지속 관계·업셀 |

> MSP의 본 매출은 **운영**입니다. 헬스체크로 고객 환경의 리스크를 선제 파악하면 운영 제안의 정밀도가 오르고, 진단에서 나온 리스크(EOL·인증서·백업 미비 등)가 그대로 **운영 서비스 수주 품목**이 됩니다.

## 3. 왜 만들었나 (문제)

운영 중인 환경은 잘 돌아가 보여도 리스크가 조용히 쌓입니다. 그리고 그 대부분은 **사고로 터질 때**에야 발견됩니다.

- 지원 종료(EOL)된 버전 — 보안 패치가 끊겨 취약점에 노출
- 인증서 만료 임박 — 어느 날 갑자기 서비스 접속 불가
- 백업은 있는데 복구 테스트 미수행 — 정작 필요할 때 복구 실패
- DB·드라이버 버전 비호환 — 업그레이드 시 접속 장애
- 백업 복구 테스트를 한 번도 안 해 롤백도 불확실

이런 리스크는 **사고가 터지기 전에** 선제적으로 찾아야 합니다. 지금은 담당자 경험에 의존해 누락이 생깁니다. MoveGuard는 이 점검을 **규칙·AI로 표준화·자동화**하고, 그 결과를 **영업이 쓸 수 있는 리포트**로 만듭니다. 발견된 리스크는 그대로 **MSP가 해결해 줄 서비스 품목**이 됩니다.

## 4. 무엇을 하나 (핵심 흐름)

```
입력  →  진단  →  판정  →  조치
```

1. **입력** — 진단 대상(운영 환경)의 구성 정보를 넣습니다. 서버(자산)·소프트웨어 버전·인증서·백업 등.
   - 진단은 자산을 스캔하는 게 아니라, 입력된 **운영 환경 구성(현재 상태)**을 점검해 손봐야 할 지점을 찾습니다.
2. **진단** — 운영 3영역, 규칙 13개 + AI로 리스크를 자동 탐지합니다.
3. **판정** — 리스크에 점수를 매겨 **운영 위험 등급(LOW/MEDIUM/HIGH)** 과 **즉시 조치/양호**를 정합니다.
4. **조치** — 리스크 항목마다 "왜 위험한지 + 무엇으로 해결하는지(MSP 서비스)"를 함께 제시합니다.

## 5. 어떻게 판정하나 (쉬운 설명)

두 가지 기준을 씁니다.

**① 위험 점수(RPN)** — 위험의 크기·우선순위를 매김
```
RPN = 심각도 × 발생가능성 × 검출난이도   (각 1~10, 최대 1000)
```
심각할수록, 자주 생길수록, 미리 찾기 어려울수록 점수가 높습니다. 제조·항공에서 쓰는 **FMEA** 위험평가 방식입니다.

**② 긴급 규칙** — 지금 바로 손봐야 할 치명적 항목
- "긴급"으로 지정된 규칙이 **1건이라도** 걸리면, 점수와 무관하게 **즉시 조치 필요**로 판정합니다.

→ 결과가 "양호 / 즉시 조치 필요"로 명확하게 나옵니다.

## 6. 무엇을 보나 (운영 3영역 · 규칙 13개)

모두 **시스원 MSP가 파는 서비스(패치·보안·백업·DR)에 직결**되는 운영 리스크입니다.

| 위험요인 | 규칙 수 | 대표 규칙 | MSP 서비스 |
| --- | --- | --- | --- |
| OS·DBMS 호환성 | 5 | OS/DB 지원종료(EOL) · 종료 임박 · 연장지원 · 최소 Java 미달 · JDBC 드라이버 | 패치·업그레이드·운영대행 |
| 보안·접근통제 | 4 | 민감 포트 노출 · 평문 · 인증서 만료 임박 · 갱신계획 누락 | 보안 서비스 |
| 백업·복구 | 4 | 최근 백업 없음 · 복구 테스트 미수행 · 체계 미비 · 오프사이트 미보관 | 백업·DR 서비스 |

> **비활성(전환 전용)**: 공인IP 변경·DNS 변경·javax→jakarta 전환·메이저 건너뛰기 — 이전(migration) 시점 전용이라 운영 범위에서 제외.

> 호환성의 **지원 종료(EOL) 기준**은 수기로 관리하면 금방 낡기 때문에, 외부 공개 데이터(endoflife.date)와 **자동 동기화**해 항상 최신으로 유지합니다. 네트워크가 안 되면 내장 스냅샷으로 대체해 오프라인에서도 동작합니다.

## 7. 데모 사례 (가나다커머스)

가상 고객 "가나다커머스"가 IDC에서 **운영 중인 리눅스 서버 환경(CentOS 7)**을 진단한 결과:

- **판정: HIGH, 즉시 조치 필요** (지원 종료된 OS·DB 운영 = 치명적)
- 리스크 **9건** 발견, 그중 **7건이 긴급(즉시 조치)** 항목
- 가장 위험한 항목: **서버 OS(CentOS 7) 지원 종료 (RPN 420)** — web01·db01 모두, 2024-06-30 종료로 보안 패치 없음 (DB MySQL 9.6도 함께 EOL)
- 요인별: OS·DBMS 호환성 5건(최고 420), 보안 2건(240), 백업 2건(210)

핵심은 이걸 **사고가 터지기 전에 미리** 찾았다는 점입니다. 영업 관점에서 이 리포트 한 장이 **"우리가 당신 환경을 이만큼 안다 + 해결해줄 수 있다"는 증거**가 됩니다.

## 8. 판정이 믿을 만한가 (검증)

실제 이전 성패 데이터가 없어서, **가상 이전 사업을 대량 생성해 성공·실패를 시뮬레이션**하고 규칙 성능을 측정했습니다.

- **규칙**: 재현율 **1.000** (실패할 사업을 하나도 놓치지 않음), 정밀도 **0.73** (보수적 — 일부 과잉 차단)
- **머신러닝**(6,000건 학습): F1 **0.871** 로 규칙(**0.850**)보다 높음 → 과잉 차단을 줄임
- **결론(하이브리드)**: 반드시 막아야 할 것은 **규칙**(설명 가능), 우선순위·예측은 **ML**

> ⚠️ 위 수치는 **시뮬레이션 데이터 기준**입니다. 규칙 자체는 실제 장애 유형에 기반하며, 실제 이전 데이터가 쌓이면 재학습해 정확도를 올리는 것이 향후 과제입니다.

## 9. 부가 기능

- **입력 간소화** — 코드/DB를 몰라도 넣을 수 있게:
  - **엑셀 업로드**: 양식을 내려받아 작성 → 업로드하면 검증 후 저장하고 바로 진단. 틀리면 "어느 시트 몇 행이 왜 틀렸는지" 알려주고 전부 저장하지 않음.
  - **웹 폼**: 화면에서 사업을 만들고 자산·IP·DNS·인증서·소프트웨어·백업을 추가/수정/삭제, 화면마다 "다시 진단".
  - **WAR/JAR 분석**: 배포 파일을 올리면 ① 설정 파일의 **하드코딩 IP**(공인/사설 구분), ② **컴파일된 Java 버전**(class 포맷), ③ **javax/jakarta 서블릿 사용**, ④ **서블릿 스펙**, ⑤ **라이브러리 목록**을 자동으로 추출합니다. 확인 후 IP는 의존성(IP-03), Java 버전은 자산 소프트웨어로 추가하면 진단에 반영됩니다. 파일은 메모리에서만 분석하고 저장하지 않습니다.
- **재진단 비교** — 조치 후 다시 진단하면 **직전 대비 변화(등급·발견 건수·최고 RPN)**를 상단에 보여줍니다. 영업에서 "고치면 이만큼 좋아진다"를 숫자로 제시하는 장면.
- **AI 경영요약 자동 작성** — 진단 결과를 고객 보고용 문장으로 **규칙 기반으로 자동 생성**(등급·최상위 리스크·권고 MSP 서비스). 외부 AI API를 쓰지 않아 **고객 데이터가 회사 밖으로 나가지 않음**. 더 긴 보고서를 위한 **사내 로컬 LLM(Ollama) 연동**은 오프라인 스크립트(`report/`)로 준비돼 있으며, 앱 통합은 로드맵.
- **전환 과정 시뮬레이션** — 전환 당일 작업(백업→중단→이전→재설정→검증→롤백)을 이산사건 시뮬레이션으로 모델링해, **정비창 안에 끝나는지·엔지니어 몇 명 필요한지**를 추정.

## 10. 시스템 구성 (단순화)

```
사용자(웹 브라우저)  →  MoveGuard 웹앱(Spring Boot)  ↔  데이터베이스(MySQL)
                                  │
                                  ├─ 진단 엔진 (규칙 13)
                                  └─ 분석·학습 / 보고서 생성 (Python, 사내 GPU)
외부 공개 EOL 데이터(endoflife.date)  ──(자동 동기화)──▶  MoveGuard
```

- 일반적인 **웹 시스템 한 대 수준** — 도입·운영 부담이 작습니다.
- 보고서 생성도 사내 GPU에서 처리 → **고객 데이터 외부 미유출**.

## 11. 기대 효과 (MSP 사업부 관점)

- **기술영업 기회 창출** — "무료 사전 위험진단"으로 일반 영업이 접근하기 어려운 고객·담당자에게 다가가 **미팅 → 신뢰 → 수주**로 연결.
- **제안 차별화·수주 경쟁력** — 사전 위험진단 리포트를 제안서에 첨부 → "잘하겠습니다"가 아니라 **근거로 설득**.
- **운영 서비스 수주·업셀** — 진단에서 나온 리스크(EOL·인증서·백업 등)가 그대로 **패치·보안·백업·DR 수주 품목** → 자연스러운 추가 수주.
- **고객 사고·이탈 방지** — 운영 리스크를 선제 발견·조치 → 장애 예방, 운영 신뢰 → 계약 유지·확대.
- **사전 점검 표준화** — 담당자 경험 의존을 규칙으로 표준화 → 속인성·누락 제거.

## 12. 진행 경과 (무엇까지 됐나)

- ✅ 진단 엔진: 운영 **3영역**(버전·호환성·보안·백업), 규칙 **13개** 활성 (전환 전용 규칙 비활성)
- ✅ 입력: **엑셀 업로드 + 웹 폼**(자산·IP·DNS·인증서·소프트웨어·백업 CRUD) + **WAR/JAR 분석**
- ✅ **재진단 비교**(직전 대비 변화 표시)
- ✅ 시뮬레이션·학습: 데이터 생성 → 성패 라벨 → 규칙 성능 분석 → ML 학습(규칙 baseline 초과)
- ✅ 전환 과정 시뮬레이션(이산사건), AI 보고서 생성
- ✅ 화면(웹 UI): 사업 목록 · 상세(입력·편집) · 진단 결과

## 13. 향후 계획

1. **제안서 첨부용 리포트 출력**(PDF 1~2장) — 영업이 고객에게 바로 건넬 기술영업 결과물
2. 실제 완료된 이전 사업 데이터로 **재학습** → 정확도 향상
3. 진단을 넘어 **전환 실행·검증·롤백 관리**까지 (진단 도구 → 이전 관리 도구)

## 14. 기술 스택

- **백엔드/웹**: Java 17 · Spring Boot · MySQL · Thymeleaf
- **분석·학습**: Python (scikit-learn), 전환 시뮬레이션은 SimPy
- **AI 요약**: 규칙 기반 자동 생성(앱 내장) · (옵션) 로컬 LLM Ollama 리포트 스크립트
- **외부 데이터**: endoflife.date (버전 지원 종료 기준)

## 15. 용어 설명

| 용어 | 뜻 |
| --- | --- |
| **MSP** | Managed Service Provider. 고객의 클라우드·인프라를 대신 구축·운영해주는 사업(전환 후 운영이 핵심 매출) |
| **기술영업** | 기술 전문성을 앞세워 고객의 기술 의사결정권자를 설득·수주하는 영업 (일반 영업이 접근하기 어려운 영역) |
| **FMEA** | 고장모드·영향 분석. 위험을 심각도·발생·검출로 평가하는 방식 (제조·항공에서 표준) |
| **RPN** | 위험 우선순위 수 = 심각도 × 발생가능성 × 검출난이도 |
| **EOL** | End of Life. 제조사의 지원(보안 패치 등)이 끝난 버전 |
| **javax → jakarta** | Java 서블릿 표준의 패키지 이름 변경. Tomcat 10부터 적용되어, 그냥 올리면 앱이 안 뜸 |
| **공인IP / 사설IP** | 외부에서 접근 가능한 주소 / 내부 전용 주소 |
| **WAS** | 웹 애플리케이션 서버 (예: Tomcat) |
| **재현율 / 정밀도** | 실패를 놓치지 않는 정도 / 차단한 것 중 실제 실패 비율 |
| **기준 / 현재 (BEFORE / AFTER)** | 점검 기준 구성 / 현재 운영 구성 (둘을 비교해 바뀐 값·위험을 찾음) |
