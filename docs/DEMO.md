# MoveGuard 7분 시연 영상 대본 (심사 발표용)

**MSP 운영 환경 헬스체크 · 기술영업 도구.** 심사위원: MSP Biz 부문장 · AX Biz 본부장 · MSP고객지원(IDC) 실장.

**한 줄 메시지:** 고객 운영 환경을 무료로 헬스체크 → EOL·인증서·백업 리스크를 선제 발견 → **그대로 시스원 MSP 운영·보안·백업·DR 수주로 연결**. 판정은 **규칙 + ML 하이브리드**, 리포트 요약은 **규칙 기반 자동 생성**(외부 AI 미사용).

**흐름:** 문제 → 진단(HIGH) → 대표 리스크 4가지 → 판정·AI → 리포트 → 개선 재진단 → 마무리

---

## 0. 녹화 전 준비 (체크리스트)

```bash
docker compose up -d        # MySQL (이미 떠 있으면 생략)
./gradlew bootRun           # 앱 (8080)
```

- [ ] 브라우저 <http://localhost:8080/> → 가나다커머스 **진단 실행**이 **HIGH · 9건 · 최고 420**으로 나오는지 확인
- [ ] 한글이 `?`/깨짐이면 시드가 깨진 것 → 재적재 (utf8mb4)
- [ ] 브라우저 확대 125~150%, 북마크바·알림 OFF
- [ ] 화면 녹화: `Win + G`(Game Bar) 또는 QuickTime / OBS
- [ ] (개선 장면용) 상세 화면에서 web01·db01의 OS `centos`(→rocky-linux 9), db01 `mysql`(→9.7) 수정 위치 미리 확인

## 1. (0:00–0:45) 문제 제기 — 운영 리스크는 ‘터질 때’ 발견된다

**화면** — 사업 목록 (<http://localhost:8080/>)

**내레이션**

> MSP가 고객 환경을 운영할 때, 가장 무서운 건 ‘잘 돌아가 보이는데 안에서 리스크가 쌓이는’ 겁니다.
> 지원이 끝난 버전은 보안 패치가 끊겨 있고, 인증서는 만료일이 다가오는데 아무도 안 보고 있고,
> 백업은 있는데 복구는 한 번도 안 해봤습니다. 이런 건 **사고가 터지고 나서** 발견됩니다.
>
> MoveGuard는 이걸 **미리** 찾아내는 운영 환경 헬스체크 도구입니다. 그리고 찾아낸 리스크는 그대로
> **시스원 MSP가 해결해 드릴 서비스**가 됩니다.

**보여줄 것** — 화면 상단 범위 패널: `OS·DBMS 호환성 · 보안 · 백업 (규칙 13)` + `규칙 + AI 하이브리드`

> 가나다커머스가 IDC에서 운영 중인 리눅스 서버 환경(CentOS 7)을 진단해 보겠습니다.

## 2. (0:45–1:30) 진단 실행 → 판정

**조작** — 가나다커머스 `진단 실행` 클릭

**화면** — 결과 상단 판정 카드

**내레이션**

> 결과는 **HIGH, 즉시 조치 필요**입니다. 지금 바로 손봐야 하는 리스크가 있다는 뜻입니다.
> 리스크 **9건**, 그중 **긴급이 7건**. 가장 위험한 항목 점수는 **420**입니다.

**짚을 것 (판정 카드)**

| 항목 | 값 | 의미 |
| --- | --- | --- |
| 운영 위험 등급 | `HIGH` | 가장 위험한 리스크의 RPN이 400 이상 |
| 판정 | `즉시 조치 필요` | ‘긴급’ 규칙이 1건이라도 걸리면 즉시 조치 |
| 최고 RPN | `420` | 서버 OS(CentOS 7) 지원 종료 운영 — 보안 패치 없음 |
| 발견 건수 | `9` | 운영 규칙 13개 중 걸린 리스크 |

**조작** — `▸ 진단 입력 — 무엇을 보고 판단했나` 펼친다

> 뭘 보고 내린 판정인지 보겠습니다. 서버를 스캔하는 게 아니라, **입력된 운영 환경 구성(현재 상태)**을 점검합니다.
> web01·db01 모두 **CentOS 7**으로 운영 중인데 2024년에 이미 지원이 끝났고, db01의 MySQL 9.6도 지원 종료, 인증서 만료일이 다가오고, 복구 테스트는 안 돼 있습니다.

**조작** — 입력 섹션 다시 접기

## 3. (1:30–3:15) 대표 리스크 4가지 짚기 — 그리고 ‘MSP가 무엇으로 해결하나’

> 9건을 다 읽지 않고, **대표 4가지**만 짚습니다. 각 카드의 점수·제목·설명·조치를 그대로 읽으면 됩니다.

### 3-1. 서버 OS·DB가 이미 지원 종료(EOL) (RPN 420 · 긴급 · 상위 3건)

> **가장 위험한 항목입니다.** web01·db01이 운영 중인 **CentOS 7은 2024-06-30에 지원이 끝났습니다.**
> 리눅스 OS에 보안 패치가 더는 안 나오는데 서비스를 그 위에서 돌리고 있는 거죠. db01의 MySQL 9.6도 마찬가지입니다.
> 취약점이 나와도 고칠 방법이 없는 상태입니다. 조치는 ‘지원되는 OS/버전으로 업그레이드’ — 이게 바로 **MSP 패치·업그레이드·운영대행** 서비스이고, **CentOS 7 EOL 전환은 지금 IDC 운영의 최대 현안**입니다.

### 3-2. 인증서 만료 임박 (RPN 192 · 긴급)

> 인증서가 곧 만료됩니다. 만료되면 **어느 날 갑자기 서비스 접속이 끊깁니다.**
> 만료 전에 갱신하고 상시 모니터링해야 하는데, 이게 **MSP 보안·운영** 서비스입니다.

### 3-3. 복구 테스트 미수행 (RPN 210 · 주의)

> 백업은 있는데 **복구 테스트를 한 번도 안 했습니다.** 정작 장애 때 복구가 안 되면 백업은 무의미합니다.
> 정기 복구 테스트·오프사이트·DR 구성 — **MSP 백업·DR** 서비스로 해결합니다.

### 3-4. JDBC 드라이버 버전이 DB 요구치 미달 (RPN 200 · 긴급)

> 드라이버가 목표 DB 버전에 못 미칩니다. 업그레이드하면 접속 장애가 납니다.
> endoflife에도 없는 이런 **드라이버 호환**까지 저희가 수동으로 관리합니다 — 디테일이 ‘진짜 안다’는 신호입니다.

**대표 리스크를 짚고 나서**

> 핵심은 **발견된 모든 리스크가 그대로 시스원 MSP 서비스 품목**이 된다는 점입니다.
> 진단 한 번이 곧 운영 수주 제안서가 됩니다.

## 4. (3:15–4:15) 어떻게 판정하나 — 점수와 AI

**화면** — 발견 목록 왼쪽 RPN 숫자들, `즉시 조치` 배지

**내레이션**

> 점수는 임의가 아니라 제조·항공에서 쓰는 **FMEA** 방식입니다. **RPN = 심각도 × 발생가능성 × 검출난이도.**
> 그리고 점수와 별개로 **‘긴급’** 항목은 하나라도 걸리면 ‘즉시 조치’로 못 박습니다. 지금 9건 중 7건이 긴급입니다.
>
> **(AX 포인트)** 판정에는 **AI가 접목돼 있습니다.** 규칙은 ‘왜 긴급인지’를 설명 가능하게,
> **머신러닝**은 우선순위·예측을 맡고(시뮬레이션 F1 0.87), 고객 리포트 문장은 **규칙 기반으로 자동 작성**합니다. 사내 로컬 LLM 연동은 오프라인 옵션으로 준비돼 있습니다.
> 중요한 건 **외부 AI를 쓰지 않고 사내 GPU에서만 처리** — 고객 데이터가 회사 밖으로 나가지 않습니다.

## 6. (5:15–6:30) 조치 후 재진단 — ‘고치면 이만큼 좋아진다’

**조작** — 사업 상세로 돌아가 web01·db01의 OS `centos`를 **수정** → `rocky-linux` 9.4 / 9 로, db01 `mysql`을 9.7 / 9.7 로 바꿔 저장

> 가장 위험했던 EOL을 조치했다고 해봅시다. 서버 OS를 지원되는 Rocky Linux 9로 올리고, DB도 지원 버전으로 올린 뒤 다시 진단합니다.

**조작** — `다시 진단`

**화면** — 결과 상단 **비교 배너**

> 보시면 **직전 대비** — **HIGH → MEDIUM**, 발견 **9건 → 5건**, 최고 RPN **420 → 270**.
> 배너가 초록으로 바뀌었죠. **조치 효과가 숫자로** 보입니다.
> 영업 관점에서 이게 가장 강력합니다 — ‘저희가 손보면 이만큼 좋아집니다’를 눈으로 증명합니다.

*(녹화 후 OS를 centos 7, db01 mysql을 9.6으로 원복해 HIGH 상태 유지)*

## 7. (6:30–7:00) 마무리

> 정리하면 — 운영은 ‘장애 나면 대응’이 아니라 **‘터지기 전에 잡는 일’**입니다.
> MoveGuard는 고객 운영 환경을 **무료로 헬스체크**해 리스크를 선제 발견하고,
> 그걸 **시스원 MSP의 운영·보안·백업·DR 수주로** 연결합니다. 판정은 규칙+ML, 리포트는 규칙 기반 자동 생성이고 외부 AI를 쓰지 않아 데이터가 밖으로 안 나갑니다.
>
> 기술영업이 고객에게 먼저 다가가는 **입구**가 되어 드립니다. 감사합니다.

| 질문 | 답변 |
| --- | --- |
| 운영 환경을 어떻게 입력하나 | 엑셀·웹 폼 입력, 또는 배포 파일(WAR) 업로드 시 버전·드라이버·설정 자동 추출 |
