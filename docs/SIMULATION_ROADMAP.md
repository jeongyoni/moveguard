# 시뮬레이션 → 학습 로드맵

MoveGuard의 규칙 기반 진단(위험요인 4/5 완성) 위에, **가상 이전 시나리오를 생성해 학습 데이터를 만들고, 위험을 예측·설명하는 모델로 확장**하기 위한 계획.

## 왜 하는가
- 지금 진단은 **결정론적 규칙**이다. "규칙이 못 잡는 패턴"이나 "위험 우선순위 예측"은 못 한다.
- 학습을 하려면 **정답(라벨) 데이터**가 필요한데, 실제 이전 성패 데이터가 없다.
- → **시뮬레이션으로 가상 이전 사례를 대량 생성**해 데이터 공백을 채운다.

## 확정된 방향 (결정 완료)
- **접근: 직접 만든 시나리오 생성기.** Rockwell Arena(툴)나 RL 환경이 아니라, 가상 운영 환경 시나리오를 코드로 생성해 **기존 진단 엔진에 투입**하는 방식.
- **핵심 원칙: 규칙과 독립된 "결과(성패)" 신호를 둔다.** 규칙 출력만 학습하면 규칙을 베끼는 순환이 되므로, 시나리오마다 **확률적 성패 라벨**(숨은 요인 + 노이즈)을 부여한다. (여기서 Arena식 '확률적 과정 모델링' 사고를 차용)
- **하이브리드 유지: 규칙 ↔ ML은 경쟁이 아니라 보완.** 규칙 = 반드시 막아야 할 것(blocking), ML = 예측·우선순위·설명.
- **진단 엔진 재사용.** 생성기는 "완성된 엔진에 입력을 흘려보내는" 구조라 엔진(현재 완성)을 그대로 쓴다.

## 단계

### Phase 0 — 로드맵 고정 (현재)
- 이 문서. 방향·순서 합의.

### Phase 1 — 시나리오 생성기 (CPU만)
- 가상 운영 환경 시나리오 N개를 랜덤·현실 조합으로 생성 (자산·IP·DNS·인증서·소프트웨어 버전, 기준/현재)
- 각 시나리오를 진단 엔진에 투입 → findings·RPN·위험등급·차단여부 산출
- 결과를 **데이터셋(테이블 또는 CSV)** 으로 적재: `(입력 특징, 진단 결과)`
- 산출물: 생성 트리거(API 또는 CLI) + 데이터셋 N행
- 가장 작은 첫걸음: **100개 생성 → 진단 → CSV**

### Phase 2 — 결과(성패) 라벨링 (CPU만)
- 시나리오마다 **확률적 성패 라벨** 부여 (숨은 요인 기반 성공확률 + 노이즈)
- 산출물: 라벨된 데이터셋 `(입력 특징, 진단 결과, 실제 성패)`

### Phase 3 — 규칙 성능 분석 (CPU만, 학습 전에도 가치)
- 규칙의 blocked/점수를 시뮬레이션 성패와 대조 → 정밀도/재현율 등 지표
- 산출물: "규칙이 놓치는/과잉 차단하는 케이스" 리포트 → 규칙 개선 피드백

### Phase 4 — 학습 모델 (GPU, DGX Spark)
- 입력 특징 → 성패(또는 위험도) 예측 모델 학습
- 규칙 vs 학습모델 비교, 규칙 빈틈 보완
- 산출물: 모델 + 평가 지표
- 자원: GPU 본격 필요, 데이터·체크포인트용 디스크 100GB+

### Phase 5 — 서빙/설명 (선택)
- 예측을 규칙 결과와 함께 제공(하이브리드)
- (선택) LLM으로 진단 리포트·조치 가이드 자연어 생성 — 추론만이라 GPU 가벼움

## 자원 요약 (DGX Spark 슬라이스)
| 단계 | RAM | 디스크 | GPU |
| --- | --- | --- | --- |
| Phase 1~3 (생성·라벨·분석) | 4~8 GB | 20~30 GB | 불필요 |
| Phase 4 (학습) | 16~32 GB | 100 GB+ | 필요(공유) |
| Phase 5 (LLM 추론) | 8~16 GB | 50 GB+ | 가벼운 공유 |

## 미결정 (진행하며 정할 것)
- 성패 라벨을 만드는 **확률 모델의 구체 형태** (어떤 숨은 요인·가중치로 성공확률을 계산할지)
- 학습 모델이 예측할 **타깃** (성패 이진 / 위험 점수 회귀 / 우선순위)
- **모델 종류** (초기: 로지스틱·트리 → 이후 신경망)
- **ML 스택** (JVM 내 DJL vs 별도 Python 파이프라인)
- 생성 시나리오의 **현실성 검증** 방법 (분포가 실제 이전과 유사한지)

## 순서 원칙
> 진단 엔진 완성(✓) → 로드맵 고정(현재) → 생성기 → 데이터셋 → 규칙 분석 → 학습.
> Phase 1~3까지는 GPU 없이 진행되며, 이 구간에서 "데이터가 쌓인다"를 먼저 확보한 뒤 학습으로 넘어간다.
